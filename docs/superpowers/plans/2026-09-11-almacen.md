# El almacén (TASK-4, paso 1 de TASK-55) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Abrir o crear la base de datos SQLite de un tablero, con el modo WAL activo y una única
función de transacción de escritura de la que dependen las seis garantías de
`docs/spec/garantias.md#concurrencia-atomicidad-y-garantías-observables`, y dar el primer paso real
(no sintético) de la prueba del presupuesto de arranque de
`docs/spec/presupuestos.md#el-presupuesto-de-arranque`.

**Architecture:** Sigue la sección 3.3 (`internal/store`) del documento de arquitectura: un único
paquete que abre el fichero SQLite con los pragmas correctos por DSN, versiona su esquema con
`PRAGMA user_version`, y expone `WithTx` como el único punto de escritura. No conoce ninguna `Task`;
el esquema de esta fase es sintético a propósito, porque el modelo de datos real llega en TASK-10
(paso 2 de TASK-55) y no en este. El tipo de error transversal de la sección 4 del documento de
arquitectura (`internal/model.Error`) nace aquí, porque `WithTx` ya necesita devolver el de la
garantía 5.

**Tech Stack:** Go 1.27.1, `modernc.org/sqlite` v1.58.0 (sin `cgo`, ya elegido y medido en
`docs/decisiones/lenguaje-y-rendimiento.md#el-controlador-de-sqlite-es-moderncorgsqlite-sin-cgo`),
`database/sql` de la biblioteca estándar. Ninguna otra dependencia.

**Spec:** `docs/spec/garantias.md`, `docs/spec/presupuestos.md`, `TASK-55` y
`docs/superpowers/specs/2026-09-10-arquitectura-implementacion-design.md` (secciones 3.3, 4 y 7.1).

## Global Constraints

- Presupuesto de arranque: 25 ms de reloj para leer un tablero de 300 tareas, en la máquina de
  referencia (`docs/spec/presupuestos.md#el-presupuesto-de-arranque`). Esta fase mide solo el
  camino que el almacén controla (abrir + leer), no el comando `ls`/`prime` completo, que todavía
  no existe.
- Las seis garantías de `docs/spec/garantias.md#concurrencia-atomicidad-y-garantías-observables`:
  ninguna escritura se observa a medias; una escritura de varias tareas es todo o nada; dos
  procesos no asignan el mismo identificador; dos escrituras simultáneas sobre la misma tarea no se
  pierden ni se mezclan; sin el bloqueo de escritura se espera hasta 5000 ms y se falla con código 8
  y el mensaje exacto `the board is busy, another process is writing to it`; las lecturas nunca
  fallan ni se bloquean por una escritura en curso. Este plan las prueba todas salvo la tercera (que
  dos procesos no asignan el mismo identificador): esa depende de la asignación de identificadores
  de tarea, que todavía no existe con el esquema sintético de este paso, y su prueba queda para el

  asignación. El mecanismo del que depende (la serialización de escritores de `WithTx`) ya queda
  probado aquí igualmente.
- Ninguna librería externa aparte de `modernc.org/sqlite`, por la sección 5 del documento de
  arquitectura.
- **El código Go (identificadores, comentarios, docstrings y mensajes, incluidos los de los
  tests) va entero en inglés, sin ninguna excepción**, según el `CLAUDE.md` del proyecto: "un
  fichero `.go` no lleva ni una palabra en español". La documentación de este propio plan, en
  `docs/superpowers/`, sigue en español; esa es la única capa donde el español es correcto.
- Nunca em-dash en ningún texto.

// Package model defines biso's domain types that depend on no storage
// mechanism and no I/O: pure data and validation.
package model

// Error is biso's cross-cutting error type. It is born in the deepest
// layer that detects a case from the specification and travels unchanged
// up to the layer that translates it to text or to JSON: no intermediate
// package reinterprets or wraps it, it only propagates it.
//
// ExitCode, Code and Message are always present. Hint is set whenever the
// case has one and left empty otherwise; it never reaches the JSON envelope
// of docs/spec/contrato-json.md#los-errores-en-json, which has no hint key.
// The five detail fields accompany only the code they correspond to, per
// the table in docs/spec/contrato-json.md#los-errores-en-json, and stay at
// their zero value when they do not apply.
type Error struct {
	ExitCode int    // the exit code, see docs/spec/codigos-de-salida.md
	Code     string // the identifier, see docs/spec/contrato-json.md#los-identificadores-de-error
	Message  string // the text that follows "error: " on stderr
	Hint     string // the text that follows "hint: " on stderr, empty when the case has none

	Field     string   // on exit code 3, and exit code 2 errors that name a flag
	Given     string   // always accompanies Field
	Valid     []string // on errors that reject a value against a known set
	Details   []*Error // only on batch_invalid and dry_run_failed, same shape, one per failure
	VCSOutput []string // only on vcs_commit_failed and vcs_push_failed
}

// Error implements the standard library's error interface.
func (e *Error) Error() string {
	return e.Message
}
```

// Package store is the only biso layer that knows what SQLite is. It opens
// or creates a board's file and exposes the write transaction that the six
// guarantees of docs/spec/garantias.md#concurrencia-atomicidad-y-garantías-observables
// depend on. It does not know what a Task is, only rows and columns.
package store

import (
	"database/sql"
	"fmt"

	_ "modernc.org/sqlite"
)

// busyTimeoutMillis is the limit from guarantee 5 of
// docs/spec/garantias.md#concurrencia-atomicidad-y-garantías-observables: if
// the program cannot get the write lock it needs, it waits at most this
// long before failing with exit code 8.
const busyTimeoutMillis = 5000

// Store wraps a SQLite database opened over a board's file.
type Store struct {
	db *sql.DB
}

// Open opens the file at path, creating it if it does not exist, in WAL
// mode, with foreign keys on and with the write lock already requested at
// the BEGIN of every transaction (see WithTx, task 4).
func Open(path string) (*Store, error) {
	return open(path, busyTimeoutMillis)
}

func open(path string, busyTimeoutMs int) (*Store, error) {
	dsn := fmt.Sprintf(
		"file:%s?_journal_mode=WAL&_busy_timeout=%d&_foreign_keys=1&_txlock=immediate",
		path, busyTimeoutMs,
	)
	db, err := sql.Open("sqlite", dsn)
	if err != nil {
		return nil, fmt.Errorf("open %s: %w", path, err)
	}
	db.SetMaxOpenConns(1)

	return &Store{db: db}, nil
}

// Close closes the connection to the store.
func (s *Store) Close() error {
	return s.db.Close()
}
```

Crea `internal/store/migrations.go`:

```go
package store

import "fmt"

// migrations is the ordered list of schema scripts. Each one's index plus
// one is the value PRAGMA user_version reaches after applying it.
//
// TASK-4 (step 1 of TASK-55) asks for the opening, WAL and transaction
// mechanism, not a task's final schema: that arrives with TASK-10 (step 2,
// the logical data model). This first script creates a synthetic table,
// bench_row, that serves to test the mechanism itself (opening, migration,
// transaction and concurrency) without pre-empting any decision about the
// real model. A later step adds the migrations that create the real
// tables.
var migrations = []string{
	`CREATE TABLE bench_row (
		id      INTEGER PRIMARY KEY,
		payload TEXT NOT NULL
	);`,
}

// migrate brings s's schema up to date, applying in order the scripts from
// migrations that PRAGMA user_version does not yet reflect.
func (s *Store) migrate() error {
	var version int
	if err := s.db.QueryRow("PRAGMA user_version").Scan(&version); err != nil {
		return fmt.Errorf("read schema version: %w", err)
	}

	for i := version; i < len(migrations); i++ {
		if err := s.applyMigration(migrations[i], i+1); err != nil {
			return err
		}
	}
	return nil
}

func (s *Store) applyMigration(script string, toVersion int) error {
	tx, err := s.db.Begin()
	if err != nil {
		return fmt.Errorf("begin migration %d: %w", toVersion, err)
	}
	if _, err := tx.Exec(script); err != nil {
		tx.Rollback()
		return fmt.Errorf("apply migration %d: %w", toVersion, err)
	}
	if _, err := tx.Exec(fmt.Sprintf("PRAGMA user_version = %d", toVersion)); err != nil {
		tx.Rollback()
		return fmt.Errorf("set schema version to %d: %w", toVersion, err)
	}
	return tx.Commit()
}
```

```go
package store

import (
	"database/sql"
	"errors"
	"fmt"

	"modernc.org/sqlite"

	"biso/internal/model"
)

// sqliteBusy is SQLite's SQLITE_BUSY result code, stable forever in its C
// API: https://www.sqlite.org/rescode.html#busy
const sqliteBusy = 5

// WithTx runs fn inside a single write transaction, the transaction that
// the six guarantees of
// docs/spec/garantias.md#concurrencia-atomicidad-y-garantías-observables
// depend on. The connection was opened with _txlock=immediate (see Open),
// so the write lock is already requested at BEGIN: if another process
// holds it, this call waits at most the time configured in Open before
// failing, never partway through fn.
//
// If fn returns an error, the transaction is rolled back entirely and that
// error is returned as-is, unwrapped: the caller can recognize its own
// with errors.Is or errors.As. If BEGIN or COMMIT itself fails with
// SQLITE_BUSY, the *model.Error from the concurrency guarantee is
// returned instead.
func (s *Store) WithTx(fn func(*sql.Tx) error) error {
	tx, err := s.db.Begin()
	if err != nil {
		return busyOrWrap(err, "begin transaction")
	}

	if err := fn(tx); err != nil {
		tx.Rollback()
		return err
	}

	if err := tx.Commit(); err != nil {
		return busyOrWrap(err, "commit transaction")
	}
	return nil
}

func busyOrWrap(err error, action string) error {
	var sqliteErr *sqlite.Error
	if errors.As(err, &sqliteErr) && sqliteErr.Code() == sqliteBusy {
		return &model.Error{
			ExitCode: 8,
			Code:     "busy",
			Message:  "the board is busy, another process is writing to it",
			Hint:     "retry in a moment; nothing was written",
		}
	}
	return fmt.Errorf("%s: %w", action, err)
}
```

package store

import (
	"database/sql"
	"path/filepath"
	"testing"
	"time"
)

// TestReadBudgetOnThreeHundredRows is the first real (non-synthetic) step
// of the startup budget test from
// docs/spec/presupuestos.md#el-presupuesto-de-arranque: 25ms of wall clock
// to read a 300-task board. It does not yet exercise the compiled binary
// or the ls/prime commands, which arrive with TASK-13 and TASK-15 (steps 5
// and 7 of TASK-55): it measures the path the store already controls,
// opening the file and reading its 300 rows, which is a floor of the full
// budget and not the final measurement. The step that adds ls/prime
// replaces it with the measurement on the real binary.
func TestReadBudgetOnThreeHundredRows(t *testing.T) {
	dir := t.TempDir()
	path := filepath.Join(dir, "board.sqlite")

	seed, err := Open(path)
	if err != nil {
		t.Fatalf("open for seeding: %v", err)
	}
	for i := 1; i <= 300; i++ {
		i := i
		if err := seed.WithTx(func(tx *sql.Tx) error {
			_, err := tx.Exec("INSERT INTO bench_row (id, payload) VALUES (?, ?)", i, "payload")
			return err
		}); err != nil {
			t.Fatalf("seed row %d: %v", i, err)
		}
	}
	seed.Close()

	start := time.Now()

	s, err := Open(path)
	if err != nil {
		t.Fatalf("open for reading: %v", err)
	}
	defer s.Close()

	rows, err := s.db.Query("SELECT id, payload FROM bench_row")
	if err != nil {
		t.Fatalf("query: %v", err)
	}
	count := 0
	for rows.Next() {
		var id int
		var payload string
		if err := rows.Scan(&id, &payload); err != nil {
			t.Fatalf("scan row: %v", err)
		}
		count++
	}
	if err := rows.Err(); err != nil {
		t.Fatalf("iterate rows: %v", err)
	}
	rows.Close()

	elapsed := time.Since(start)
	if count != 300 {
		t.Fatalf("count = %d, want 300", count)
	}
	if elapsed > 25*time.Millisecond {
		t.Fatalf(
			"opening and reading 300 rows took %s, want less than 25ms (docs/spec/presupuestos.md#el-presupuesto-de-arranque)",
			elapsed,
		)
	}
}

## Correcciones posteriores a la revisión adversarial

Los bloques de código de arriba son el plan tal como se escribió. La revisión adversarial de este
paso encontró ocho cosas y las ocho se corrigieron después, así que **lo que manda hoy es el código,
no esos bloques**. Lo que cambió de la interfaz del paquete:

- `Open` recibe el `id` del tablero además de la ruta, `Open(id, path string)`, porque el mensaje del
  error de base de datos ilegible lo nombra. `openAt` es la versión interna que también recibe el
  tiempo de espera y la lista de migraciones, y es la que usan las pruebas.
- `model.Error` guarda `Hints []string` en vez de `Hint string`: hay dos casos en la especificación
  que imprimen dos líneas de `hint`, y uno es precisamente el de este paquete.
- El almacén construye los dos errores que fija la especificación: el de la garantía 5 (código 8,
  `busy`) desde cualquier camino que se tope con el bloqueo, incluidos abrir y migrar, y el de la
  base de datos ilegible (código 21, `database_unreadable`), que antes no existía. `CheckIntegrity`
  ejecuta `PRAGMA integrity_check` y devuelve ese segundo error.
- `ErrTxInProgress` es lo que devuelven el manejador del `Store` y un `WithTx` anidado mientras hay
  una transacción viva, en vez de colgarse esperando la única conexión.
- La migración ocurre entera dentro de una transacción inmediata que vuelve a leer
  `PRAGMA user_version`, y la lista de migraciones se inyecta en vez de mutarse desde una prueba.

El porqué de cada una está en la sección 3.3 del documento de arquitectura y en las notas de TASK-4.
