# El almacén (paso 1 de la sección 15 de SPEC.md) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Abrir o crear la base de datos SQLite de un tablero, con el modo WAL activo y una única
función de transacción de escritura de la que dependen las seis garantías de la sección 4.10 de
`SPEC.md`, y dar el primer paso real (no sintético) de la prueba del presupuesto de arranque de la
sección 4.13.

**Architecture:** Sigue la sección 3.3 (`internal/store`) del documento de arquitectura: un único
paquete que abre el fichero SQLite con los pragmas correctos por DSN, versiona su esquema con
`PRAGMA user_version`, y expone `WithTx` como el único punto de escritura. No conoce ninguna `Task`;
el esquema de esta fase es sintético a propósito, porque el modelo de datos real llega en el paso 2
de la sección 15 y no en este. El tipo de error transversal de la sección 4 del documento de
arquitectura (`internal/model.Error`) nace aquí, porque `WithTx` ya necesita devolver el de la
garantía 5.

**Tech Stack:** Go 1.27.1, `modernc.org/sqlite` v1.58.0 (sin `cgo`, ya elegido y medido en el
apartado 14.1 de `DECISIONES.md`), `database/sql` de la biblioteca estándar. Ninguna otra
dependencia.

**Spec:** `docs/SPEC.md` (secciones 4.10, 4.13 y 15) y
`docs/superpowers/specs/2026-09-10-arquitectura-implementacion-design.md` (secciones 3.3 y 4).

## Global Constraints

- Presupuesto de arranque: 25 ms de reloj para leer un tablero de 300 tareas, en la máquina de
  referencia (sección 4.13 de `SPEC.md`). Esta fase mide solo el camino que el almacén controla
  (abrir + leer), no el comando `ls`/`prime` completo, que todavía no existe.
- Las seis garantías de la sección 4.10 de `SPEC.md`: ninguna escritura se observa a medias; una
  escritura de varias tareas es todo o nada; dos procesos no asignan el mismo identificador; dos
  escrituras simultáneas sobre la misma tarea no se pierden ni se mezclan; sin el bloqueo de
  escritura se espera hasta 5000 ms y se falla con código 7 y el mensaje exacto `the board is busy,
  another process is writing to it`; las lecturas nunca fallan ni se bloquean por una escritura en
  curso. Este plan las prueba todas salvo la tercera (que dos procesos no asignan el mismo
  identificador): esa depende de la asignación de identificadores de tarea, que todavía no existe
  con el esquema sintético de este paso, y su prueba queda para el plan del paso 2 de la sección 15
  (el modelo de datos lógico), que es quien introduce esa asignación. El mecanismo del que depende
  (la serialización de escritores de `WithTx`) ya queda probado aquí igualmente.
- Ninguna librería externa aparte de `modernc.org/sqlite`, por la sección 5 del documento de
  arquitectura.
- Documentación y comentarios en español; identificadores de código en inglés (`CLAUDE.md` del
  proyecto). Nunca em-dash en ningún texto.
- Los mensajes de commit no llevan coautoría ni mención de haber sido generados por un agente.
- Todo el trabajo de este plan ocurre en este worktree, nunca en el checkout principal.

// Package model define los tipos de dominio de biso que no dependen de
// ningún mecanismo de almacenamiento ni de E/S: son datos y validación pura.
package model

// Error es el tipo de error transversal de biso. Nace en la capa más
// profunda que detecta un caso de la especificación y viaja sin cambios
// hasta la capa que lo traduce a texto o a JSON: ningún paquete intermedio
// lo reinterpreta ni lo envuelve, solo lo propaga.
//
// Los tres primeros campos están siempre presentes. Los cinco de detalle
// acompañan solo al code que les corresponde según la tabla de la sección
// 12.2 de docs/SPEC.md, y quedan en su valor cero cuando no aplican.
type Error struct {
	ExitCode int    // el código de salida de la sección 2 de SPEC.md
	Code     string // el identificador de la sección 12.3 de SPEC.md
	Message  string // el texto que sigue a "error: " en stderr

	Field     string   // en los del código 3, y los del 2 que nombran un flag
	Given     string   // acompaña siempre a Field
	Valid     []string // en los que rechazan un valor contra un conjunto conocido
	Details   []*Error // solo en batch_invalid y dry_run_failed, misma forma, uno por fallo
	VCSOutput []string // solo en vcs_commit_failed y vcs_push_failed
}

// Error implementa la interfaz error de la biblioteca estándar.
func (e *Error) Error() string {
	return e.Message
}
```

// Package store es la única capa de biso que sabe qué es SQLite. Abre o
// crea el fichero de un tablero y expone la transacción de escritura de la
// que dependen las seis garantías de la sección 4.10 de docs/SPEC.md. No
// sabe qué es una Task, solo filas y columnas.
package store

import (
	"database/sql"
	"fmt"

	_ "modernc.org/sqlite"
)

// busyTimeoutMillis es el límite de la garantía 5 de la sección 4.10 de
// docs/SPEC.md: si el programa no consigue el bloqueo de escritura que
// necesita, espera como mucho esto antes de fallar con el código 7.
const busyTimeoutMillis = 5000

// Store envuelve una base de datos SQLite abierta sobre el fichero de un
// tablero.
type Store struct {
	db *sql.DB
}

// Open abre el fichero de path, creándolo si no existe, en modo WAL, con
// las claves foráneas activas y con el bloqueo de escritura pedido ya en el
// BEGIN de cada transacción (ver WithTx, tarea 4).
func Open(path string) (*Store, error) {
	return open(path, busyTimeoutMillis)
}

func open(path string, busyTimeoutMs int) (*Store, error) {
	dsn := fmt.Sprintf(
		"file:%s?_journal_mode=WAL&_busy_timeout=%d&_foreign_keys=1&_txlock=immediate",
		path, busyTimeoutMs,
	)
	db, err := sql.Open("sqlite", dsn)
	if err != nil {
		return nil, fmt.Errorf("open %s: %w", path, err)
	}
	db.SetMaxOpenConns(1)

	return &Store{db: db}, nil
}

// Close cierra la conexión con el almacén.
func (s *Store) Close() error {
	return s.db.Close()
}
```

Crea `internal/store/migrations.go`:

```go
package store

import "fmt"

// migrations es la lista ordenada de scripts de esquema. El índice de cada
// uno más uno es el valor al que PRAGMA user_version llega tras aplicarlo.
//
// El paso 1 de la sección 15 de docs/SPEC.md pide el mecanismo de apertura,
// WAL y transacción, no el esquema definitivo de una tarea: eso llega en el
// paso 2, con el modelo de datos de la sección 5. Este primer script crea
// una tabla sintética, bench_row, que sirve para probar el mecanismo mismo
// (apertura, migración, transacción y concurrencia) sin adelantar ninguna
// decisión sobre el modelo real. Un paso posterior añadirá las migraciones
// que crean las tablas reales.
var migrations = []string{
	`CREATE TABLE bench_row (
		id      INTEGER PRIMARY KEY,
		payload TEXT NOT NULL
	);`,
}

// migrate deja el esquema de s al día, aplicando en orden los scripts de
// migrations que PRAGMA user_version todavía no recoge.
func (s *Store) migrate() error {
	var version int
	if err := s.db.QueryRow("PRAGMA user_version").Scan(&version); err != nil {
		return fmt.Errorf("leer la version del esquema: %w", err)
	}

	for i := version; i < len(migrations); i++ {
		if err := s.applyMigration(migrations[i], i+1); err != nil {
			return err
		}
	}
	return nil
}

func (s *Store) applyMigration(script string, toVersion int) error {
	tx, err := s.db.Begin()
	if err != nil {
		return fmt.Errorf("empezar la migracion %d: %w", toVersion, err)
	}
	if _, err := tx.Exec(script); err != nil {
		tx.Rollback()
		return fmt.Errorf("aplicar la migracion %d: %w", toVersion, err)
	}
	if _, err := tx.Exec(fmt.Sprintf("PRAGMA user_version = %d", toVersion)); err != nil {
		tx.Rollback()
		return fmt.Errorf("fijar la version del esquema en %d: %w", toVersion, err)
	}
	return tx.Commit()
}
```

package store

import (
	"database/sql"
	"errors"
	"fmt"

	"modernc.org/sqlite"

	"biso/internal/model"
)

// sqliteBusy es el código de resultado SQLITE_BUSY de SQLite, estable desde
// siempre en su API C: https://www.sqlite.org/rescode.html#busy
const sqliteBusy = 5

// WithTx ejecuta fn dentro de una única transacción de escritura, la
// transacción de la que dependen las seis garantías de la sección 4.10 de
// docs/SPEC.md. La conexión se abrió con _txlock=immediate (ver Open), así
// que el bloqueo de escritura se pide ya en el BEGIN: si otro proceso lo
// tiene, esta llamada espera como mucho el tiempo configurado en Open antes
// de fallar, nunca a mitad de fn.
//
// Si fn devuelve un error, la transacción se deshace entera y ese error se
// devuelve tal cual, sin envolverlo: quien llama puede reconocer el suyo con
// errors.Is o errors.As. Si el propio BEGIN o el COMMIT fallan por
// SQLITE_BUSY, se devuelve el *model.Error de la garantía 5.
func (s *Store) WithTx(fn func(*sql.Tx) error) error {
	tx, err := s.db.Begin()
	if err != nil {
		return busyOrWrap(err, "empezar la transaccion")
	}

	if err := fn(tx); err != nil {
		tx.Rollback()
		return err
	}

	if err := tx.Commit(); err != nil {
		return busyOrWrap(err, "confirmar la transaccion")
	}
	return nil
}

func busyOrWrap(err error, action string) error {
	var sqliteErr *sqlite.Error
	if errors.As(err, &sqliteErr) && sqliteErr.Code() == sqliteBusy {
		return &model.Error{
			ExitCode: 7,
			Code:     "busy",
			Message:  "the board is busy, another process is writing to it",
		}
	}
	return fmt.Errorf("%s: %w", action, err)
}

package store

import (
	"database/sql"
	"path/filepath"
	"testing"
	"time"
)

// TestReadBudgetOnThreeHundredRows es el primer paso real (no sintético) de
// la prueba del presupuesto de arranque de la sección 4.13 de docs/SPEC.md:
// 25 ms de reloj para leer un tablero de 300 tareas. Todavía no ejercita el
// binario compilado ni los comandos ls/prime, que llegan en los pasos 5 y 7
// de la sección 15: mide el camino que el almacén ya controla, abrir el
// fichero y leer sus 300 filas, que es un suelo del presupuesto completo y
// no la medida final. El paso que añada ls/prime la sustituye por la medida
// sobre el binario de verdad.
func TestReadBudgetOnThreeHundredRows(t *testing.T) {
	dir := t.TempDir()
	path := filepath.Join(dir, "board.sqlite")

	seed, err := Open(path)
	if err != nil {
		t.Fatalf("abrir para sembrar: %v", err)
	}
	for i := 1; i <= 300; i++ {
		i := i
		if err := seed.WithTx(func(tx *sql.Tx) error {
			_, err := tx.Exec("INSERT INTO bench_row (id, payload) VALUES (?, ?)", i, "payload")
			return err
		}); err != nil {
			t.Fatalf("sembrar la fila %d: %v", i, err)
		}
	}
	seed.Close()

	start := time.Now()

	s, err := Open(path)
	if err != nil {
		t.Fatalf("abrir para leer: %v", err)
	}
	defer s.Close()

	rows, err := s.db.Query("SELECT id, payload FROM bench_row")
	if err != nil {
		t.Fatalf("consultar: %v", err)
	}
	count := 0
	for rows.Next() {
		var id int
		var payload string
		if err := rows.Scan(&id, &payload); err != nil {
			t.Fatalf("leer la fila: %v", err)
		}
		count++
	}
	if err := rows.Err(); err != nil {
		t.Fatalf("recorrer las filas: %v", err)
	}
	rows.Close()

	elapsed := time.Since(start)
	if count != 300 {
		t.Fatalf("count = %d, quiero 300", count)
	}
	if elapsed > 25*time.Millisecond {
		t.Fatalf(
			"abrir y leer 300 filas tardó %s, quiero menos de 25ms (seccion 4.13 de SPEC.md)",
			elapsed,
		)
	}
}
